## 🖼️ Qué hay de nuevo

### El wallpaper real ahora viaja dentro del instalador

En v1.0.0 el instalador copiaba la carpeta de wallpapers, pero **nunca dejaba el fichero en la ruta exacta** que aplica la sesión. Resultado en instalaciones limpias: `feh` fallaba en silencio y el escritorio arrancaba **negro**.

- ✅ `wallpaper.png` ahora va **embebido en el payload** del instalador (nada se descarga en tiempo de ejecución)
- ✅ La fase de assets lo instala en `/usr/share/backgrounds/whitehatso/wallpaper.png` — la ruta exacta que `bspwmrc` aplica con `feh --bg-fill`
- ✅ Verificado byte a byte: el wallpaper del instalador es **idéntico** al del escritorio de referencia (md5 `1af0032b…`)
- ✅ Bonus: se corrige también la portada del README, que mostraba el login en lugar del escritorio real

**Si instalaste v1.0.0 y tienes el fondo negro**, basta con ejecutar el nuevo instalador (es idempotente) o copiar el wallpaper a mano:

```bash
sudo mkdir -p /usr/share/backgrounds/whitehatso
sudo cp wallpaper.png /usr/share/backgrounds/whitehatso/wallpaper.png
```

## 📦 El instalador

Autocontenido: **no descarga nada del repo en tiempo de ejecución** — lleva dentro todos los configs (bspwm, sxhkd, kitty, polybar, rofi, picom, dunst, fastfetch), los scripts propios (`whs-*`, `settarget`, `whitehatso-close/lock`), el fondo del login y ahora también el wallpaper.

```bash
curl -fsSL https://raw.githubusercontent.com/D1se0/environment-ubuntu-installer/main/install-whitehatso.sh -o install-whitehatso.sh
chmod +x install-whitehatso.sh
sudo bash install-whitehatso.sh
```

Te irá preguntando: usuario, paquetes base, tuning de rendimiento, login temático lightdm, fixes VMware y prompt para root. Modo desatendido: `WHS_ASSUME_YES=1 WHS_USER=tu_usuario sudo -E bash install-whitehatso.sh`.

**Seguridad por diseño:** lista de paquetes **protegidos** (xorg, lightdm, bspwm, mesa…) que el debloat jamás desinstala, y **backups** automáticos de tus configs en `~/.config/backups/whitehatso-<fecha>/`.
